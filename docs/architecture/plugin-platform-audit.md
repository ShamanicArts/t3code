# Plugin Platform Plan Audit

Plan audit verdict: **BLOCKED**. The architecture direction is plausible, but the bundle is not handoff-ready. Several contracts cannot implement their own stated behavior, and multiple factual claims are stale.

## BLOCKER

1. **S0 does not define an executable plugin ABI.** PLAN-105 “Goal” and “Loader” says a manifest points to an Effect Layer loaded at boot ([PLAN-105 §Goal](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:7), [§Loader](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:69)). But `PluginManifest` has no server entrypoint, export name, module format, host/API compatibility version, or build artifact; `PluginSource` supplies only a path and options ([plugins.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:95), [source shape](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:122)). A packaged server cannot load arbitrary external TypeScript from this contract. Define the executable packaging/module ABI before S0.

2. **The extension envelopes cannot enter the current command/event engine.** PLAN-105 “Contracts” and “Extension vocabulary delegation” promises generic command/event cases ([PLAN-105 §Contracts](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:50), [§Delegation](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:82)). `ExtensionCommandEnvelope` lacks `type`, `commandId`, required aggregate identity, and timestamp; `threadId` is optional. The event envelope lacks the persisted event base entirely ([plugins.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:106)). The engine unconditionally reads command type/ID and maps every non-project command to a required thread aggregate ([OrchestrationEngine.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/Layers/OrchestrationEngine.ts:67), [processing](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/Layers/OrchestrationEngine.ts:199)). Receipts are bound to command hash/type/aggregate ([OrchestrationEngine.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/Layers/OrchestrationEngine.ts:217)). Specify a real union member, aggregate rules, event-intent wrapping, and whether fragments may emit multiple aggregates.

3. **There is no namespace ownership registry or plugin-owned state model.** PLAN-105 says the “owning plugin” receives a registered namespace, but namespace lists appear only in optional capability restrictions; `PluginContributions` has no mandatory namespace ownership declaration ([plugins.ts capabilities](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:23), [contributions](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:83)). With capabilities omitted under full trust, ownership is unknowable. The proposed pure fragment also receives only the core read model, which contains no generic extension-state map ([orchestration.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/orchestration.ts:458)); the current decider/projector accept no immutable registry parameter ([decider.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/decider.ts:222), [projector.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/projector.ts:199)). Define mandatory ownership, duplicate-namespace resolution, project-scoped lookup, and namespaced decision state without introducing Effect service lookup into the pure center.

4. **“Opaque payload, no migration” is false, and missing-plugin replay semantics are undefined.** PLAN-105 says extension payloads are opaque and broken plugins are skipped without blocking boot ([PLAN-105 §Loader](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:69), [§Delegation](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:82)). SQL parses payload as `unknown`, but then decodes the complete row through the closed `OrchestrationEvent` union ([OrchestrationEventStore.ts](/home/shamanic/Projects/shuv2code/apps/server/src/persistence/Layers/OrchestrationEventStore.ts:31), [row decode](/home/shamanic/Projects/shuv2code/apps/server/src/persistence/Layers/OrchestrationEventStore.ts:184)). Startup replays persisted events before the engine is available ([OrchestrationEngine.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/Layers/OrchestrationEngine.ts:437)). Choose explicit behavior for absent owners—fail boot, quarantine, retain last projection, or skip with recoverable per-plugin cursors—and require payload schema versions/upcasters. Also decide whether unknown-namespace rejection should create a permanent rejected receipt; current invariant failures do ([OrchestrationEngine.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/Layers/OrchestrationEngine.ts:413)).

5. **One decider case plus one projector case does not complete extension routing.** PLAN-105 covers only `decider.ts` and `projector.ts`, and PLAN-107 jumps to timeline rendering ([PLAN-105 §Delegation](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:82), [PLAN-107 §Inventory](/home/shamanic/Projects/shuv2code/PLAN-107-plugin-platform-s15-surface-slots.md:44)). Actual event flow also has:

   - A closed SQL projector routing table ([ProjectionPipeline.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/Layers/ProjectionPipeline.ts:77)).
   - A closed WebSocket detail-event predicate ([ws.ts](/home/shamanic/Projects/shuv2code/apps/server/src/ws.ts:476)).
   - Client reduction that hardcodes Voice payload-to-message conversion ([threadReducer.ts](/home/shamanic/Projects/shuv2code/packages/client-runtime/src/state/threadReducer.ts:283)).

   Timeline renderers alone cannot supply projections, snapshots, delivery, or client state. These seams belong in S0/S1.5.

6. **The surface contract cannot express PLAN-107, and `declarativeBase` cannot guarantee mobile correctness.** PLAN-107 “Slot model” requires ordering, visibility, exclusivity, ownership, and declared event kinds ([PLAN-107 §Slot model](/home/shamanic/Projects/shuv2code/PLAN-107-plugin-platform-s15-surface-slots.md:17)). `SurfaceDescriptor` contains only slot/id/title/base/webEntry—no scope, region, multiplicity, priority, visibility rule, exclusivity, owner, or timeline event kinds ([plugins.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:55)). `declarativeBase` is an arbitrary string plus `Record<string, unknown>`, so validation accepts kinds mobile cannot render ([plugins.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:49)). Real surfaces require live queries and actions: preview sends annotations, diff consumes Git/composer state, and files require environment/thread callbacks ([ChatView.tsx](/home/shamanic/Projects/shuv2code/apps/web/src/components/ChatView.tsx:6413)). Define a closed, versioned mobile primitive/action/data-binding vocabulary—or weaken the invariant to a placeholder/fallback contract.

7. **PLAN-109 assumes a native mobile Call product that does not exist.** PLAN-109 “Web/mobile” says iOS/Android Call keeps its existing architecture and needs no rewrite, while its gate requires a mobile Call E2E pass ([PLAN-109 §Web/mobile](/home/shamanic/Projects/shuv2code/PLAN-109-plugin-platform-s3-voice-plugin.md:40), [§Verification](/home/shamanic/Projects/shuv2code/PLAN-109-plugin-platform-s3-voice-plugin.md:71)). The mobile navigator includes Thread, Terminal, Review, Files, Settings, and Git routes, but no Voice/Call route ([Stack.tsx](/home/shamanic/Projects/shuv2code/apps/mobile/src/Stack.tsx:460)). Mobile currently only hides managed Voice threads; there is no native Call feature surface. Either add mobile Call implementation to scope or redefine the declarative mobile gate honestly.

8. **Voice storage namespacing is undefined and the migration inventory is materially stale.** PLAN-109 lists 036–039, 048, 049 and claims fixed core migrations can back repositories in the plugin’s “own namespace” ([PLAN-109 §Migration inventory](/home/shamanic/Projects/shuv2code/PLAN-109-plugin-platform-s3-voice-plugin.md:18)). In reality:

   - Migration 038 is generic command-receipt provenance.
   - Voice-related migrations 050–054, including call events, calls, ownership, handoff, and message modality, are omitted ([Migrations.ts](/home/shamanic/Projects/shuv2code/apps/server/src/persistence/Migrations.ts:119)).
   - The persistence layer contains six repositories, including `VoiceCallEvents`, not the stated inventory ([VoiceControl.ts](/home/shamanic/Projects/shuv2code/apps/server/src/persistence/Layers/VoiceControl.ts:3)).
   - Repositories and migrations hardcode global SQL table names; `storageNamespace` is merely an unchecked string ([plugins.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:29), [053 migration](/home/shamanic/Projects/shuv2code/apps/server/src/persistence/Migrations/053_VoiceCallOwnership.ts:7)).

   Define whether namespace means ownership metadata, table prefixing, an attached database, or a scoped repository factory. As written, storage step 4 has no executable semantics.

9. **Voice is still hardwired outside the declared migration inventory.** PLAN-109 claims removing the decider/projector cases makes the core feature-free and skipping Voice yields a clean server ([PLAN-109 §Contracts](/home/shamanic/Projects/shuv2code/PLAN-109-plugin-platform-s3-voice-plugin.md:31), [§Verification](/home/shamanic/Projects/shuv2code/PLAN-109-plugin-platform-s3-voice-plugin.md:71)). Core still directly:

   - Queries Voice tables to guard thread/project deletion ([OrchestrationEngine.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/Layers/OrchestrationEngine.ts:91)).
   - Routes Voice events in the SQL projection pipeline ([ProjectionPipeline.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/Layers/ProjectionPipeline.ts:102)).
   - Wires Voice persistence/services into the main runtime ([server.ts](/home/shamanic/Projects/shuv2code/apps/server/src/server.ts:295)).
   - Constructs Voice RPC handlers in the core WebSocket layer ([ws.ts](/home/shamanic/Projects/shuv2code/apps/server/src/ws.ts:201)).

   The extraction boundary needs a complete dependency inventory, including RPC contribution/removal semantics and lifecycle policy hooks.

10. **PLAN-108 freezes a VCS port that contradicts the settled placement-flexible north star.** PLAN-108 says `VcsDriver` remains exactly as audited ([PLAN-108 §Core changes](/home/shamanic/Projects/shuv2code/PLAN-108-plugin-platform-s2-vcs-plugins.md:39)). The port exposes raw local process execution and bare `cwd` arguments throughout, with no environment, instance, or placement target ([VcsDriver.ts](/home/shamanic/Projects/shuv2code/apps/server/src/vcs/VcsDriver.ts:34)). The registry directly constructs local Git/JJ drivers and caches by only kind plus path ([VcsDriverRegistry.ts](/home/shamanic/Projects/shuv2code/apps/server/src/vcs/VcsDriverRegistry.ts:64), [construction](/home/shamanic/Projects/shuv2code/apps/server/src/vcs/VcsDriverRegistry.ts:88)). A local plugin cannot act on a cloud instance through this port without breaking it. Introduce an opaque repository/environment target now, or narrow the north star.

11. **The five Voice steps are not independently revertible.** PLAN-109 “Sequencing” deletes legacy cases before relocation and says every step can be reverted independently ([PLAN-109 §Sequencing](/home/shamanic/Projects/shuv2code/PLAN-109-plugin-platform-s3-voice-plugin.md:54)). Once step 1 writes extension event types, reverting to the prior closed event union makes replay fail. Existing databases also contain legacy `thread.voice-*-appended` rows that still require their old projectors ([orchestration.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/orchestration.ts:1634), [projector.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/projector.ts:555)). Specify dual-read/dual-registration compatibility, an upcaster, and downgrade replay tests. Otherwise remove “independently revertable.”

## SHOULD-FIX

12. **PLAN-106 changes a persisted provider identity while promising zero behavioral change.** Its example uses `driverId: "shuvcode"` and says hydration/session continuity remain unchanged ([PLAN-106 §Provider shape](/home/shamanic/Projects/shuv2code/PLAN-106-plugin-platform-s1-first-party-provider-plugins.md:25), [§Core changes](/home/shamanic/Projects/shuv2code/PLAN-106-plugin-platform-s1-first-party-provider-plugins.md:38)). The actual OpenCode-v2 driver kind and default instance routing slug are `opencodeV2`; `shuvcode` is the binary/package name ([OpenCodeV2Driver.ts](/home/shamanic/Projects/shuv2code/apps/server/src/provider/Drivers/OpenCodeV2Driver.ts:43), [provider identity compatibility](/home/shamanic/Projects/shuv2code/packages/contracts/src/providerInstance.ts:141)). Keep `driverId: opencodeV2`, or define aliases and data migration.

13. **S1 cannot simply make the static array disappear while leaving second-party movement to S4.** The current `BUILT_IN_DRIVERS` contains all six providers, and hydration imports and iterates it to synthesize legacy configurations ([builtInDrivers.ts](/home/shamanic/Projects/shuv2code/apps/server/src/provider/builtInDrivers.ts:23), [hydration](/home/shamanic/Projects/shuv2code/apps/server/src/provider/Layers/ProviderInstanceRegistryHydration.ts:55)). PLAN-106 extracts only Codex/OpenCode-v2 but says the array disappears; PLAN-110 extracts the remaining four later. Define a transitional mixed contribution list, and acknowledge hydration must change. Also note that `ProviderDriver` is deliberately a plain value, not an Effect service ([ProviderDriver.ts](/home/shamanic/Projects/shuv2code/apps/server/src/provider/ProviderDriver.ts:1)).

14. **The stated startup composition seam is wrong.** PLAN-105 says plugin Layers merge through `serverRuntimeStartup.ts`, after core services and before HTTP listening ([PLAN-105 §Loader](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:69)). Layer composition occurs in `server.ts`; `serverRuntimeStartup` explicitly waits until HTTP is already listening, with command readiness acting as the gate ([serverRuntimeStartup.ts](/home/shamanic/Projects/shuv2code/apps/server/src/serverRuntimeStartup.ts:428), [server.ts](/home/shamanic/Projects/shuv2code/apps/server/src/server.ts:750)). Identify the pre-layer-build discovery seam and phrase the invariant as “before command readiness,” unless HTTP itself must remain unopened.

15. **PLAN-107 audits the wrong panel seam and omits important ownership/lifetime behavior.** `RightPanelSheet` is only generic chrome around children ([RightPanelSheet.tsx](/home/shamanic/Projects/shuv2code/apps/web/src/components/RightPanelSheet.tsx:6)); the actual switch is in `ChatView`, which also owns terminal, pull-request, agents, and multi-instance preview/file surfaces ([ChatView.tsx](/home/shamanic/Projects/shuv2code/apps/web/src/components/ChatView.tsx:6413), [rightPanelStore.ts](/home/shamanic/Projects/shuv2code/apps/web/src/rightPanelStore.ts:21)). Voice also requires a persistent portal tree across inline/sheet remounts to preserve live visual state ([VoiceSurfaceHost.tsx](/home/shamanic/Projects/shuv2code/apps/web/src/components/voice/VoiceSurfaceHost.tsx:24)). Produce a full matrix covering scope, cardinality, persisted state, callbacks, and keep-alive policy.

16. **Dynamic web loading lacks a module/runtime and HTTP contract.** PLAN-107 “Web loading path” proposes `/plugins/<id>/` dynamic imports and arbitrary Vite URLs, while rejecting import maps/module federation ([PLAN-107 §Web loading](/home/shamanic/Projects/shuv2code/PLAN-107-plugin-platform-s15-surface-slots.md:59)). Current HTTP serves one static root or redirects the whole loopback app to one dev URL; it has no per-plugin roots or proxying ([http.ts](/home/shamanic/Projects/shuv2code/apps/server/src/http.ts:374)). Define:

   - Export shape and SDK/API version.
   - React singleton/shared-dependency strategy.
   - Asset/chunk base paths and cache busting.
   - Path containment and URL allowlisting.
   - Cross-origin module/HMR CORS.
   - Load-failure fallback.
   - How an *uninstalled* plugin becomes visible in the contribution snapshot.

17. **Project-wins scoping is not replay-stable and is underspecified for a multi-project server.** PLAN-105 permits project-relative replacement of the same plugin ID ([PLAN-105 §Contracts](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:62)). Events persist only namespace/name/payload, with no owner plugin, version, source identity, or project selection ([plugins.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:106)). Two projects can therefore select different sources/versions for one ID while the process has one namespace registry and Layer graph. Persist owner/schema identity or require compatibility, and define whether registrations are keyed by project/environment.

18. **The optional restriction model is internally inconsistent.** PLAN-105 and the explainer describe three enforced chokepoints—secrets, exec, filesystem—while the contract also advertises `network` restriction ([PLAN-105 §Non-goals](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:37), [plugins.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/plugins.ts:29)). There is no network broker in the plan. Either remove `network`, add the fourth chokepoint, or label it advisory. Also separate namespace ownership from operator-imposed capability restrictions.

19. **The dependency chain is overengineered for the project’s current scale.** PLAN-107 depends on provider extraction even though slots only need S0; PLAN-109 depends on VCS extraction without using VCS ([PLAN-107 header](/home/shamanic/Projects/shuv2code/PLAN-107-plugin-platform-s15-surface-slots.md:1), [PLAN-109 header](/home/shamanic/Projects/shuv2code/PLAN-109-plugin-platform-s3-voice-plugin.md:1)). Cut or defer:

   - Migrating every in-tree surface before the first plugin surface.
   - Relocating Git/JJ before Voice proves the platform.
   - External-source support before one real external consumer.
   - Four second-party extractions before the ABI settles.
   - `cli`, `skills`, and broad MCP contribution arrays in S0 unless immediately consumed.

   A smaller path is S0 loader/registry → Voice-specific panel/timeline seam → Voice server extraction, while retaining static provider/VCS adapters until a second consumer exists.

20. **PLAN-110’s maintenance contract and external-source story contradict themselves.** It says providers ship in monorepo `plugins/*`, then calls them the first externally checked-out consumers ([PLAN-110 §Design](/home/shamanic/Projects/shuv2code/PLAN-110-plugin-platform-s4-second-party-providers.md:28)). Its smoke can degrade to load/register only, which does not substantiate “works as today” ([PLAN-110 §Smoke policy](/home/shamanic/Projects/shuv2code/PLAN-110-plugin-platform-s4-second-party-providers.md:44)). `storageNamespace` is also the wrong settings-evolution escape hatch: provider instances already have an opaque, driver-decoded `config` envelope ([providerInstance.ts](/home/shamanic/Projects/shuv2code/packages/contracts/src/providerInstance.ts:115)).

21. **Verification gates are not testable or sufficient for the risky seams.** PLAN-105–110 use broad phrases such as “all green,” “pixel-identical,” and “one integrated pass,” without named fixtures or expected assertions. There is no existing web pixel-regression baseline in the affected test surface. Missing gates include:

   - Upgrade and downgrade replay.
   - Existing extension history with owner missing/disabled/broken.
   - Plugin re-enable and cursor catch-up.
   - Duplicate namespaces across projects.
   - Receipt retry after namespace availability changes.
   - Invalid/cyclic/non-JSON payload rejection and size bounds.
   - Plugin bundle 404, invalid export, cross-origin failure, and chunk loading.
   - Mobile unknown declarative kind/action behavior.
   - Voice data preservation when Voice is disabled.
   - Boot/listener/readiness ordering.

## NIT

22. **Cross-plan references are stale.** PLAN-105 says Voice moves in PLAN-108, but PLAN-108 is VCS and Voice is PLAN-109; it assigns frontend preview to PLAN-109 while PLAN-107 defines it ([PLAN-105 §Non-goals](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:37), [§Delegation](/home/shamanic/Projects/shuv2code/PLAN-105-plugin-platform-s0-machinery.md:82)). The actual Voice branches remain in the current decider ([decider.ts](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/decider.ts:1421)).

23. **“Promotion of 7 existing call sites” is stale and the RPC-scope analogy is misleading.** Internal domain-event streams are unscoped Effect services, while RPC authorization applies to transport methods ([OrchestrationEngine service](/home/shamanic/Projects/shuv2code/apps/server/src/orchestration/Services/OrchestrationEngine.ts:57), [RpcAuthorization.ts](/home/shamanic/Projects/shuv2code/apps/server/src/auth/RpcAuthorization.ts:23)). Decide whether trusted plugins receive unrestricted internal events instead of borrowing RPC terminology.

24. **The scaffolded contracts are not publicly exported.** `plugins.ts` exists, but the contracts package exports only the root, settings, and relay subpaths, and `src/index.ts` does not re-export plugins ([package.json](/home/shamanic/Projects/shuv2code/packages/contracts/package.json:1)). A contracts typecheck can pass without proving consumers can import the new API.

## TOP 5 MUST-FIX BEFORE HANDOFF

1. Define the executable plugin/module ABI and real command/event envelope, including aggregate, receipt, namespace-owner, and project-scoping semantics.
2. Specify durable event compatibility: payload versions/upcasters, missing-owner replay, re-enable catch-up, and downgrade behavior.
3. Replace the surface skeleton with an executable slot/declarative contract covering ownership, event kinds, actions, visibility, exclusivity, and lifetime.
4. Correct PLAN-109’s Voice inventory, storage semantics, nonexistent mobile Call assumption, and non-revertible sequence.
5. Make VCS targets environment/instance/placement-aware—or explicitly abandon the placement-flexible claim before freezing the port.
