# Product

## Register

product

## Users

Developers and technical operators who run several coding agents across local, self-hosted, desktop, web, and mobile environments. They need to move quickly between active threads, projects, terminals, source-control state, previews, and unattended work without losing ownership or execution context.

## Product Purpose

shuv2code is the local-first control plane for coding agents. It brings Codex, Claude, Cursor, Grok, and OpenCode sessions into one provider-neutral workspace while keeping local and self-hosted operation explicit and trustworthy. Success means the interface disappears into the work: users can start, steer, inspect, automate, and recover agent activity from any supported client without learning a different lifecycle for every provider.

## Brand Personality

Confident, compact, and playfully technical. The product should feel like a serious operator tool with a restrained devil-terminal identity, not a novelty interface. Copy is direct, familiar, and economical.

## Anti-references

- Generic AI dashboard spectacle: oversized gradients, glowing empty space, or decorative agent metaphors that compete with the work.
- SaaS landing-page patterns inside the product: hero metrics, promotional cards, and explanatory copy that narrates obvious controls.
- Upstream identity leakage: T3 Code names, assets, routes, or language presented as shuv2code product identity.
- Decorative devil imagery: faces, flames, pitchforks, badges, or oversized horns and tails.
- Hidden capability: shipped product surfaces must not exist only as direct routes, orphaned components, or undiscoverable gestures.

## Design Principles

1. Make capability discoverable. A shipped workflow needs a familiar, persistent entry point wherever users expect to find it.
2. Preserve operational context. Environment, project, provider, thread, and source-control ownership stay visible and stable across actions.
3. Keep one product lifecycle. Voice, permissions, interruptions, automations, mobile behavior, and provider sessions share the same provider-neutral control model.
4. Prefer earned familiarity. Reuse standard navigation, toolbar, settings, form, and status patterns; novelty is reserved for the brand mark and rare moments of delight.
5. Keep the workspace quiet. Dense information is welcome, but color, motion, and copy appear only when they change an action, decision, interpretation, or safety outcome.

## Accessibility & Inclusion

Target WCAG AA contrast for ordinary text and controls. Every primary action needs an accessible name, visible keyboard focus, and a keyboard-operable path. Dialogs must dismiss predictably, core actions must remain reachable without horizontal overflow, touch targets must remain usable on coarse pointers, and nonessential motion must respect reduced-motion preferences. Color never carries status alone.
